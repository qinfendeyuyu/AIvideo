# 操作动图说明

这段约 27 秒的 GIF 来自真实运行的本地工作台，说明如何填写生成参数以及如何处理实际返回。它**没有演示成功生成图片、视频或保存成片**。拍摄日期：2026-10-08。

![本地工作台操作动图](screenshots/generation-walkthrough.gif)

## 跟着操作

1. **检查服务**：确认 Ollama、ComfyUI 与所需模型已就绪，并查看可用提交内存。不要只看机器标称 RAM。
2. **准备剧本**：填写需求，或直接使用已经整理好的分镜与英文提示词。动图只填写了需求，没有启动文本生成。
3. **准备静帧**：填写人物、构图、光照及背景描述，选择画幅并记录 seed。
4. **提交静帧**：点击“静帧加入队列”。本次实际发送了一次请求，网关返回 **HTTP 503 / 可用提交内存不足**；请求没有变成任务，也没有 GPU 推理。先保存工作、关闭不用的软件，再重新检查，不要绕过保护。
5. **选择首帧**：真正制作时，需要先审查眼睛、手部、服装和背景。动图仅选择名为 `upload-demo-only.png` 的文件演示浏览器文件输入，内容是本仓库已公开的工作台截图，**不是人物首帧，也不是模型输出**；未上传或提交给视频模型。
6. **设置视频参数**：填写一个简单动作，选择约 2 秒短镜头。动图只指示视频提交按钮位置，**没有点击该按钮**。
7. **查看任务区**：本次确实为空。实际成功生成后，工作台才显示素材预览及“打开 / 保存素材”；下载、人工审片及整集剪辑不在本次录制范围内。

- 原始页面为 `app/static/local_free.html`，没有修改应用源文件、覆盖模型服务结果或伪造任务进度。
- 顶部步骤条、黄色边框、圆形光标是录制时叠加的教程注释，不是应用的新功能；为注释预留了页面空白。

- 录制使用独立无登录资料的浏览器，只访问本机网关；遇到非空队列会停止，不发布私人任务或素材。
- 记录了实际 503 返回、页面哈希、演示输入哈希、GIF 哈希、尺寸、帧数及步骤，见[录制记录](screenshots/walkthrough-manifest.json)。

## 重录（维护者）

脚本：[record_generation_walkthrough.cjs](../scripts/record_generation_walkthrough.cjs)。需要另行准备 Node.js、Playwright / Chromium、FFmpeg 和 FFprobe。Node.js 和 Playwright / Chromium 仅用于本次录制（Node.js 也用于供应商协议测试），工作台页面不依赖它们；FFmpeg / FFprobe 除录制编码外，也是实际生成视频的输出校验依赖。

**此脚本不是只读工具：它会尝试实际发送一次图片请求。** 它专门记录“内存预检拒绝”路径，要求真实网关队列为空且 `memory.image_ready=false`，否则退出；不得为演示主动耗尽内存或清除现有任务。它不提交文本或视频请求，也不关闭程序、修改页面文件或取消共享 ComfyUI 任务。

预检和提交不是原子操作：如果内存恰好在两者之间释放，实际请求仍可能被接受。遇到不是内存不足 503 的返回，脚本会停止录制，**此时先检查真实队列，不要直接重跑或假设没有任务**。

```powershell
# 确认 Node 能解析已安装的 playwright，FFmpeg/FFprobe 已加入 PATH。
node .\scripts\record_generation_walkthrough.cjs
```

中间帧保存在 Git 忽略的 `runtime_cache/walkthrough-*`，已校验的成品写入 `docs/screenshots/`。脚本不安装依赖、不自动下载模型。发布前检查 GIF 中每步文字和真实状态，运行文档资产测试；未来若要展示“成功生成”，必须另行录制实际成功任务并同步更新说明，不能替换状态文本冒充。
